# Reflection on AI-assisted Debugging
## Introduction
For my debugging assistant, I used Claude on the free plan. I gave it four code snippets for debugging with varying languages and complexity. For snippets 1-3 the code snippet was copied whole and Claude was asked to resolve the bug without even specifying what the bug was. The first 3 bugs were fairly straight forward and were common bugs likely with a lot of training data. Bug 4 was more complex using a snippet from a MATLAB function used for calculating the optical properties of nanoparticles, although the actual bug stemmed from MATLAB multithreading and unrelated to nanoparticle calculations.
## Strengths
For all bugs, Claude not only correctly identified what would go wrong, but would also gave an explanation of the cause and offered a correct solution. At least for common bugs, AI appears to be highly effective even with minimal information, making them highly ergonomic and efficient at resolving bugs of that type. Their clear explanation and provision of solution examples also makes them highly useful learning tools, provided that their information is correct.

Bug 4 was the hardest by far but clearly not hard enough as it was resolved by Claude all the same with minimal information. It was surprising was that Claude was able to deduce the exact package used (MNPBEM) despite not being explicitly stated, in the code or prompts. It appears that Claude was able to recognise the set up code as commonly used with MNPBEM and include that context in its analysis.
## Weaknesses
For bug 3, Claude thought a type error would occur and the buggy code would not even run, even though it did run without error. It correctly decerned that `(s, c)` was unintentionally passed to `dtype` but was unable to further deduce that it could still be accepted. This is a reasonable mistake to make even for humans due to the lack of static typing in python and numpy's extensive use of function overloading. It appears Claude was either unable or "unwilling" to go through the documentation exhaustively just to verify if a type error would actually occur.
## Human Role
For bugs 1-3, I was already familiar with these bugs so I could immediately verify their correctness and knew it was trustworthy. I did still perform testing to fully verify correctness. As previously mentioned, Claude incorrectly determined that bug 3 would not run which I could disprove myself by running the code. Therefore, it is still up to humans to perform tests to verify the statements from AI.

For bug 4, the solution Claude provided was novel to me, so I could only rely on testing rather than my own knowledge to verify the Claude's statements.
## Conclusion
In conclusion, for quick fixes to common mistakes, AI appears to be quite effective. Additionally,  AI is highly effective at inferring context and matching code to pre-existing coding patterns. However, these bug snippets have been limited to under 40 lines with no additional context. Further testing would be required to determine how AI would perform on larger code bases on more novel bugs.
